# On-demand Crossfeed wake checker (independent observation)

This module is **not** part of the server, browser extension, login, or wake path. It starts only when a person invokes the CLI. It never changes configuration, enables DevTools, launches a browser, sends a wake by default, installs packages, or runs a service. Core CLI, status, replay and CDP use the Python 3 standard library; native KDE observation also requires distro-provided dbus-python and PyGObject (plus a working KDE/KWin DBus session). No packages are installed automatically. Evidence is sampled, not a claim of complete or pixel-level coverage.

## Exact commands (run from the repository root)

```sh
python3 -m tools.wake_checker doctor
npm run wake:check -- doctor
npm run wake:check -- listen --duration 60
python3 -m tools.wake_checker listen
python3 -m tools.wake_checker listen --duration 60 --output /tmp/a-new-wake-check-run
python3 -m tools.wake_checker listen --duration 300 --status-url http://127.0.0.1:4319
python3 -m tools.wake_checker listen --duration 300 --cdp-url http://127.0.0.1:9222
python3 -m tools.wake_checker replay /path/to/sanitized/events.jsonl --output /tmp/a-new-replay-dir
python3 -B -m unittest discover -s tools/wake_checker/tests -q
node tools/wake_checker/tests/kwin_sampler_vm.js tools/wake_checker/kwin_observer.js
node --check tools/wake_checker/kwin_observer.js
npm run test:wake-checker
npm run check
```

Run Python discovery with `-s tools/wake_checker/tests`; discovery at the repository root does not find this suite. The Python tests, Node VM sampler and JavaScript syntax check run offline. Replay checks recorded event logic and timestamps; it cannot recover missing observations or establish real desktop visibility.

`listen` defaults to **passive 300 seconds** and has a hard duration limit of 3600 seconds. SIGINT/Ctrl-C and SIGTERM request cleanup and write the summary; signal handlers are installed before native startup and restored on exit. It polls the native observer in the primary loop and the explicit status/CDP endpoints in bounded threads; no native dependency is required for the fallback. Output includes a private new run directory (0700), exclusive `events.jsonl` and `summary.json` (0600), a concise health line approximately every 15 seconds, and a final sanitized summary. Existing output directories and symlink directory paths are rejected. For explicit `--output` the parent must already exist; output directory itself must not exist. The default parent `.wake-check-runs` is private and is created by a `listen` or `replay` invocation only. Do not publish screenshot files.

`doctor` checks native adapter capabilities only, never loads any KWin script, never calls the status API or CDP, and does not create a run. The included optional native adapter is `tools/wake_checker/desktop.py` with `DesktopObserver(duration, emit)`, `start/poll/close`, and `doctor()`. It needs a supported KDE/KWin Wayland DBus session, native `dbus-python` and PyGObject bindings, and the host KWin tooling; unsupported desktops or missing bindings fail capability checks without installing anything. The optional observer's event protocol has fixed `window_added`, `window_activated`, `window_changed`, `window_closed`, `desktop_changed`, `activity_changed`, `ready`, `heartbeat` and fixed booleans. No window title, app ID, arbitrary text, user credentials, URLs, or native exception strings are retained.

## 50 ms targeted background observation (metadata, not pixels)

The optional KWin callback timer runs at a requested **50 ms metadata sampling resolution** for newly identified browser candidates, not for every desktop window. A 50 ms timer is **not** a first-painted-pixel guarantee, a 50 ms delivery bound, continuous visibility proof, or a promise of zero foreground interruptions; scheduler delays and missed callbacks are observable gaps. Explicit window activation/change signals complement periodic property sampling, but an available property does **not** imply that a corresponding changed signal exists. Active, topmost, attention, per-desktop, per-activity, minimized and relative-stack readings are nullable. Each schema-v3 window-state snapshot is normalized independently to all eight boolean-or-null flag names: an omitted flag means **unknown (`null`)**, never the last observed value. Observed transport loss likewise propagates unknown evidence instead of retaining earlier foreground/background values. Relative stacking is not equivalent to actual compositor pixels or user intent.

An immutable positive *first-added* active/visual-stack result, including an activation buffered before the first add, remains an initial failure even after later restoration. Later activation, reforeground, attention and topmost rises are separate counts. Episodes and completed observed durations use the recorded event bounds (with 50 ms sampling and possible signal/scheduler uncertainty); they are **not** exact on-screen pixel exposure durations. An active episode terminated by an observed window-close has a completed observable event bound, not a fabricated last painted frame. The conservative `no_observed_foreground_at_50ms` label is possible only **after a window closes**, with its own reported complete-period sample counts and zero per-window gaps as well as healthy global coverage, and absent any foreground signal or unknown metadata. A still-open window, legacy four-flag record, missing per-window counters, gap, overflow or unobserved field is *indeterminate*, never a clean result. Browser metadata never identifies task ownership without a separate wake marker.

Native KWin observation exists only for the explicitly finite `listen --duration` run, has a hard stop/unload and does not mutate focus, activity, desktops or browser state. Native observation never takes screenshots. Browser-viewport screenshots, if intentionally enabled as an additional debugging action, are covered by the separate sensitive-capture warning below and require explicit opt-in. Strict sanitized v2 replay accepts legacy four-flag snapshots, but missing newer flags and per-window coverage remain unknown rather than false or rejected. Final CLI lines include bounded aggregate annoyance counts and, where retained, per-window completed-duration/uncertainty detail, not a 100% success claim.

Summary output is bounded by a **65,536-byte pretty-JSON cap**. At worst the bound removes episode/timeline detail, then entire per-window reports (including the window's flags, terminal sampling tick/gap counts and completed-duration detail), pending/probe rows, and selected nested `current` fields. At most 24 candidate-window reports are detailed even before size pruning; aggregate counters and `total_candidate_windows` remain, with `truncated` and, when size pruning occurs, `summary_truncation` omission indicators. A missing per-window entry or flag is never proof of complete sampling or a negative foreground observation. The 50 ms metadata sampler does **not** establish the first rendered pixels, even on a healthy run.

## Passive authenticated status

The status endpoint is opt-in and **must** be literally `http://127.0.0.1:PORT`. Nothing else (DNS aliases, HTTPS, paths, query strings, userinfo, non-loopback addresses) is accepted. It performs only bearer-authenticated **GET /status** during passive observation, with token from the exact named environment variable `--token-env` (default `CROSSFEED_API_KEY`). It does not inspect config, search credentials, use system proxies, follow redirects, or log tokens. Requests and response bodies have finite time and byte limits. Missing token, 401/403, outages, parse errors, unknown stages, and missing extension heartbeats remain categorized as unknown/error, never success. The current server exposes a daily wake cap and per-worker quota deadlines, while hourly values remain unknown unless explicitly returned. Cooldowns are evaluated against the current wall time rather than any positive stale timestamp. Worker contact, claims, queues, current failures, stage/error diagnostics and host/extension state are tracked as allowlisted aggregates. Extension heartbeat presence alone is not proof of fresh contact.

Each lane uses a fresh per-run salted HMAC fingerprint; no job ID, session ID, ticket nonce, claim token, wake/error body, label or secret is stored. Multiple wakes in the same lane/state are `ambiguous_duplicate`, not uniquely correlated attempts. A pending state clock starts at first observed sample: thresholds of 15, 60, 180 seconds are **lower bounds**, never exact wake age. The summary gives *current sampled* pending totals, suspected pending-at-threshold totals, duplicates/ambiguities, failed/expired totals, job states, claim/queue worker flags, quota blocks, host/extension health and associated safe stages/errors, separately from historical crossings. Observation gaps, count/state/stage/job progress, failures and disappearance reset the clock; disappearance is **not** success. Constant aggregate counts can hide churn, so even a lower-bound suspect is not proof of one uninterrupted ticket. Authenticated backend completion is distinct from native window candidates, selected/foreground/focus/stack/workspace signals and DOM readiness. Native activation can precede classification and is buffered; first-added active/minimized/workspace/stack booleans are retained separately from later changes. A browser window is only a candidate unless a native wake marker confirms provenance. The observer does not infer user-versus-program focus intent.

All emitted JSONL events have a per-run monotonically increasing `seq` and monotonic `elapsed_ms` measured relative to the recorder start. Live events also record `collector_wall_ms`; native packets retain `native_event_wall_ms` independently, since wall timestamps are not precise monotonic durations. Probe results separately record backend completion duration and first native candidate-add/activation offsets after dispatch, plus the interval in which an opening was not seen (when observable). Candidate timing never establishes ownership. `replay` strictly validates the sanitized event schema and re-evaluates status projections using the recorded elapsed timestamps, retaining the original nested window flags, caps, jobs, stages, and diagnostics; it consumes health/gap/capability/cleanup/probe records. The legacy `--sample-seconds` option is only a synthetic fallback for older records without timestamps. It rejects oversized rows, symlinks, invalid sequences and unsanitized fields. Replay can validate the checker’s own event logic, **not** the real desktop or end-to-end delivery.

## Optional read-only CDP

`--cdp-url http://127.0.0.1:PORT` only connects to an **already running** local DevTools endpoint. It never enables debugging or alters a browser or page. The baseline excludes pre-existing pages; subsequent observations repeatedly sample a bounded number of newly listed `https://chatgpt.com` page targets with a same-port loopback `ws://` endpoint. Each observed target gets a salted per-run fingerprint; target disappearance/errors/recovery are distinct from no target, and repeated ready samples do not count as new sessions. `--target-id EXACT_ID` explicitly overrides the baseline exclusion for that one target, for controlled fixtures. A fixed Runtime query checks the *current frame origin* on every inspection; stale `/json/list` metadata is insufficient. No foreign page origin or websocket is accepted; no redirects or proxies. The protocol rejects unsupported fragmentation, RSV bits, invalid control frames and deadline overruns. Bounded WebSocket commands are restricted to fixed, structural, read-only DOM booleans/counts (`ready`, `composer`, `generating`, `login`, `error`, `dialog`, `permission`) evaluated by a constant expression. No arbitrary page text, messages, cookies, storage, clicks, typing, `bringToFront`, or Debugger commands. Dialog/alert/permission indicators are structural **potential** signals, not verified permission or error outcomes. DOM inspection is best effort; unsupported versions/targets produce unknown/error, never inferred passes.

Browser-viewport screenshots require the **separate explicit `--screenshots` opt-in**, plus `--cdp-url`. At most four first-seen scoped targets may be captured to exclusive private PNG files, only when the frame is the ChatGPT root path (not an existing private conversation). Frame origin, navigation URL and document epoch are checked before and after capture; a changed/foreign/private frame is discarded without writing pixels. URL/epoch values are transient and never logged. They are **browser viewport pixels**, not whole-desktop pixels or a verified first rendered frame. No screenshot is taken from a status-only or native-only source. **All explicitly captured screenshots are sensitive, UNREDACTED browser-viewport pixels**, including the root SPA route: overlays, account details, notifications, draft text, or other private content can be visible at `/`. Do not publish or assume redaction. Treat them as sensitive locally.

## Explicit active diagnostic only (never done as part of tests)

```sh
python3 -m tools.wake_checker listen --duration 300 --status-url http://127.0.0.1:4319 \
  --cdp-url http://127.0.0.1:9222 --probe-model chatgpt:YOUR_LABEL \
  --allow-active-probe --probe-count 1
```

The `--probe-model`, `--allow-active-probe` and authenticated status URL are mandatory. `--probe-count` defaults to **1 only if a model was explicitly specified**; a standalone count/consent is refused. Explicit counts **1–4** are permitted, each with a fresh random `X-Crossfeed-Session` and a fixed harmless unpredictable exact-answer token. Optional `--probe-timeout SECONDS` is capped at **755 seconds** and cannot exceed `--duration`; a dispatch is further bounded by the remaining listen duration. It submits one completion per session with **no retries**, browser interactions, profile/settings changes or other API writes. HTTP sockets use a whole-request monotonic deadline, with cancellation shutting down active connections on stop. Client disconnection is **not** cancellation of a server-side job; timed-out or in-flight results are unknown/delivery-uncertain and are never counted as completed. A **fresh successful** authenticated status sample from the current dispatch iteration is required, not a remembered earlier success; the active collector must also have healthy, unbroken coverage. In-flight shutdown observations are unknown, not inherited success. Status must have succeeded and at least one native or CDP collector must be ready before dispatch; a requested CDP collector must also be ready. It compares the **actual returned completion content** byte-for-byte in memory, logging only exact/mismatch/unknown, never prompts or responses. Native window creation is independently observed only as a temporal candidate, not an exact join to the completion. No new window can be consistent with a warm delivery; it does not prove warm reuse. A request still in flight at stop has unknown outcome; the bounded HTTP timeout does not cancel a server job.

## Evidence and limits

A `ready` backend record is not proof of visible tabs, focus or completed paint. A native window addition/activation is not proof of successful authenticated task completion, and neither event establishes that a UI frame was shown. The tool cannot establish a **pixel first frame**, user-initiated focus intent, or pixel-level physical desktop visibility without a separate permitted native screen observer. Dropped samples and outages reset lower-bound inference. Native window IDs have a strict **256 cumulative IDs per listener**, with no reuse within a run. Once capacity is exhausted, or overflow/unknown events occur, coverage becomes incomplete and native evidence is fail-closed (cannot authorize an active probe). A normal observer close is reported as unsupported/closed with cleanup status separately; heartbeat or owner failures retain their original reasons. The optional KDE/KWin adapter can be unavailable; the checker does not claim cross-platform native fidelity. The checker reports source health and lacks automatic integration. It does not modify the server/extension and should not be used as an automated probe runner.
